# PGH PPO·A2C 실험 기록

## 현재 실행 설정 (2026-10-31)

현재 `penalty_detail.json`은 누적 100,000 Step, 판매 손실 감점 `sell_loss=0.15`,
소환·강화·판매 고정 감점은 모두 0이다. `goal_gold`는 설정에서 생략되어 기본값 0이다.
아래 보상 표와 5만 Step 예시는 2026-10-29의 이전 PPO 실험 기록이며 현재 설정과 구분한다.

프로젝트 루트에서 설치 및 실행한다.

```sh
python -m pip install -r requirements-ppo.txt
python scripts/ppo.py
python scripts/A2C.py
```

A2C는 같은 게임 환경·보상과 공통 학습 수치를 사용하며, PPO 확률 비율 clipping과
미니배치 반복 갱신 대신 전체 수집 배치로 한 번만 갱신한다. GAE와 Adam은 유지한다.
PPO 전용 `clip_eps`, `epochs`, `minibatch_size`는 A2C에서 사용하지 않는다.
A2C 기본 저장 폴더는 `results/a2c_pgh`, 기본 누적 목표는 100,000 Step이다.

새 실험은 별도 출력 폴더에서 시작한다.

```sh
python scripts/A2C.py --fresh --total-timesteps 100000 --output-dir results/a2c_pgh_v2
```

A2C 모델은 `a2c_policy.pt`, `a2c_best.pt`로 저장한다. `checkpoint.pt`는 이어 학습용이다.
`--fresh` 없이 실행하면 설정의 `resume`에 따라 같은 폴더의 A2C 체크포인트를 재사용한다.
설정·CSV 4개·그래프 7개도 출력 폴더에 저장된다.

## 이전 PPO 실험 설정 (2026-10-29)

기준: `penalty_detail.json` 및 `../ppo.py` (2026-10-29).
당시 `python scripts/ppo.py`로 실행할 때 적용한 설정을 정리했다.
다른 `--config`, 환경 변수, `--set`으로 덮어쓰면 실제 적용값은 달라질 수 있다.

## 설계 목표

30소동 클리어를 목표로 하며, 클리어한 판에서는 골드를 효율적으로 사용해
더 많은 골드를 남긴 전략에 추가 보상을 준다. 과도한 판매를 줄이기 위해 판매 패널티를 다시 활성화했다.
남은 골드 보상은 클리어율을 보장하지 않으며, 클리어율과 잔여 골드를 함께 평가한다.

## 보상·패널티 표

프로필은 `design_scaled`, 보상 배율 `scale`은 **0.01**이다.
아래 실제 적용값은 배율 적용 후의 값이며, 게임 내 골드와는 별개인 학습 점수다.

| 구분 | 설정 키 | 발생 조건 | 설정값 | 실제 적용값 |
| --- | --- | --- | ---: | ---: |
| 웨이브 클리어 | `clear` | 웨이브 종료 시 살아남음 | +2 | +0.02 |
| 최종 클리어 | `goal` | 학습 목표 웨이브 완료 (현재 30소동) | +100 | +1.0 |
| 보스 처치 | `boss.5` | 5소동 보스 처치 | +3 | +0.03 |
| 보스 처치 | `boss.10` | 10소동 보스 처치 | +4 | +0.04 |
| 보스 처치 | `boss.15` | 15소동 보스 처치 | +5 | +0.05 |
| 보스 처치 | `boss.20` | 20소동 보스 처치 | +6 | +0.06 |
| 보스 처치 | `boss.25` | 25소동 보스 처치 | +7 | +0.07 |
| 보스 처치 | `boss.30` | 30소동 보스 처치 | +8 | +0.08 |
| 잔여 골드 | `goal_gold` | 30소동 승리 시 남은 골드 1G당 | +0.01 | +0.0001 |
| 결계 손실 | `life` | 라이프 1 감소당 | 10 (차감) | −0.1 |
| 보스 웨이브 추가 결계 감점 | `boss_life` | 보스 웨이브의 라이프 1 감소당 추가 차감 | 0 | 없음 |
| 게임 오버 | `over` | 패배 | −50 | −0.5 |
| 공통 행동 감점 | `action_cost` | 소환·강화·판매·웨이브 시작 1회당 | 0 | 없음 |
| 소환 감점 | `cost_buy` | 소환 1회당 | 0.5 (차감) | −0.005 |
| 강화 감점 | `cost_upgrade` | 강화 1회당 | 0.5 (차감) | −0.005 |
| 웨이브 시작 감점 | `cost_start` | 웨이브 시작 1회당 | 0 | 없음 |
| 판매 고정 감점 | `cost_sell` | 판매 1회당 | 0.5 (차감) | −0.005 |
| 판매 손실 비례 감점 | `sell_loss` | 판매로 손해 본 골드 1G당 | 0.15 (차감) | −0.0015 |

`sell_loss: 0.15`와 `cost_sell: 0.5`를 활성화했다.
게임 내 판매 환급률은 60%이며, 학습 점수에서는 판매 고정 감점과 골드 손실 비례 감점을 함께 적용한다.
소환·강화 감점과 나머지 보상은 유지한다.

## 계산 방식과 예시

같은 행동이나 웨이브에서 발생한 항목은 합산하고 `scale`을 곱한다.

```text
행동 보상 = −(action_cost + 해당 행동의 cost_*) × scale
판매 보상 = −(action_cost + cost_sell + sell_loss × 판매 손실 골드) × scale
최종 승리 잔여 골드 보상 = 남은 골드 × goal_gold × scale
```

| 상황 | 계산 | 실제 보상 |
| --- | --- | ---: |
| 라이프 손실 없이 일반 웨이브 클리어 | 2 × 0.01 | +0.02 |
| 라이프 1을 잃고 일반 웨이브 클리어 | (2 − 10) × 0.01 | −0.08 |
| 타워 소환 1회 | −0.5 × 0.01 | −0.005 |
| 100G에 소환한 1레벨 타워를 60G에 판매 | −(0.5 + 0.15 × 40) × 0.01 | −0.065 |
| 최종 승리 시 100G 보유 | 100 × 0.01 × 0.01 | 추가 +0.01 |
| 최종 승리 시 1,000G 보유 | 1,000 × 0.01 × 0.01 | 추가 +0.10 |
| 최종 승리 시 3,000G 보유 | 3,000 × 0.01 × 0.01 | 추가 +0.30 |
| 30소동 보스 처치·라이프 손실 없음·1,000G 보유 후 승리 | (2 + 8 + 100 + 1,000 × 0.01) × 0.01 | +1.20 |

마지막 예시는 마지막 웨이브 시작 행동에서 받는 보상이다.
그 전에 발생한 소환·강화 감점과 이전 웨이브 보상은 판 전체 누적 보상에 별도로 포함된다.
승리 잔액은 엔진이 최종 정산을 마친 시점의 골드이며 최종 클리어 보상 골드도 포함한다.

## 적용 범위

- 잔여 골드 보상은 실제 `VICTORY` 상태이면서 30소동일 때만 지급한다.
- 패배하거나 30소동보다 짧은 학습 목표를 완료했을 때는 잔여 골드 보상이 없다.
- 일반 몬스터 처치나 골드 획득·보유 자체에는 별도 학습 보상이 없다.
- 현재 PPO는 준비 단계에서 소환·강화·판매·웨이브 시작을 선택한다. 이동과 전투 중 강화는 학습 행동에 없다.
- 다른 설정 파일에는 `goal_gold`가 없으면 기본값 0이 적용된다. 이 파일의 값과 자동 병합되지 않는다.

## 실험 저장 예시

당시 판매 패널티 실험은 새 폴더에서 5만 Step까지 학습하도록 설정했다.

```json
"run": {
  "output_dir": "results/ppo_pgh_sell_50k",
  "total_timesteps": 50000,
  "resume": true,
  "seed": 2026,
  "train_stages": 30
}
```

프로젝트 루트에서 실행하면 `results/ppo_pgh_sell_50k`에 결과가 저장된다.
`total_timesteps`는 추가 학습량이 아닌 누적 목표이며, 묶음 단위로 처리해 조금 초과할 수 있다.
`resume: true`일 때 같은 폴더의 체크포인트를 이어서 사용한다. 새 실험은 새 폴더로 구분한다.
